# VMware Cloud Foundation 9.1 管理服務元件總覽

> 文件版本：VCF 9.1.0  
> 建立日期：2026-05-29  
> 參考來源：Broadcom TechDocs / VMware Cloud Foundation 官方文件

---

## 架構概述

VCF 9.1 引入 **VCF Management Services（管理服務）** 統一架構，將原本分散的獨立 Appliance 整合至以 Kubernetes 為基礎的 **VCF Services Runtime** 叢集中運行。元件依作用範圍分為：

- **Fleet 層級**：跨所有 VCF Instance 執行全域操作（僅部署於 Primary Instance）
- **Instance 層級**：每個 VCF Instance 各自部署，執行本地任務
- **獨立元件**：擁有專屬 FQDN，不在 Services Runtime 內運行

## 元件詳細說明

### 一、Fleet 層級元件（Primary Instance 部署，全域共用）

---

#### 1. Fleet Lifecycle

| 項目 | 內容 |
|---|---|
| **FQDN** | fleetlcm.dcsn.stone.lab |
| **版本** | 9.1.0.0.25371109 |
| **狀態** | ✅ Running |
| **層級** | Fleet（全域） |

**功能說明：**

取代 VCF 9.0 的獨立 Fleet Management Appliance VM，是整個 Fleet 生命週期管理的核心元件。

- 管理整個 VCF Fleet 所有元件的升級與修補（Patching）
- 提供 Fleet 範圍的策略（Policy）執行與組態漂移（Drift）監控
- 整合 vSphere / ESX 修補流程，支援低停機（RDU）升級
- 統一儀表板呈現跨 Instance 的升級計劃與執行順序
- 升級時自動進行 Pre-check，驗證系統健康與資源容量

---

#### 2. Identity Broker

| 項目 | 內容 |
|---|---|
| **FQDN** | vidb.dcsn.stone.lab |
| **版本** | 9.1.0.0.25368698 |
| **狀態** | ✅ Running |
| **層級** | Fleet（全域） |

**功能說明：**

提供整個 VCF Fleet 的統一身分驗證與存取控制服務。

- 為所有 VCF 管理元件提供單一登入（SSO）
- 整合外部 Identity Provider（IdP），如 AD / LDAP / OIDC
- 支援 Fleet 層級 RBAC 角色指派
- 可部署為 Appliance 模式（HA 多節點）或嵌入式（embedded in vCenter）

---

#### 3. Salt RaaS

| 項目 | 內容 |
|---|---|
| **FQDN** | fleetlcm.dcsn.stone.lab |
| **版本** | 9.1.0.0.25346036 |
| **狀態** | ✅ Running |
| **層級** | Fleet（全域） |

**功能說明：**

RaaS（Returner as a Service）為 VCF Salt 組態管理系統的中央 API 服務。歷史曾稱為 SaltStack Enterprise、Aria Automation Config。

- 提供 RPC 端點接收管理指令
- 與 Salt Master 進行介接，分發組態管理任務
- 提供 Web UI 管理 Minion、使用者、角色、作業
- 支援大規模節點的遠端執行（Remote Execution）與狀態管理

---

#### 4. Software Depot

| 項目 | 內容 |
|---|---|
| **FQDN** | fleetlcm.dcsn.stone.lab |
| **版本** | 9.1.0.0.25371105 |
| **狀態** | ✅ Running |
| **層級** | Fleet（全域） |

**功能說明：**

集中式軟體倉庫，取代過去 NSX、vCenter、SDDC Manager 各自維護的分散軟體庫。

- 統一儲存所有 VCF 元件的安裝與升級 Binary
- 使用 OAuth Token 安全管理線上與離線（Disconnected）環境的更新
- 升級前須先設定 Fleet 層級 Software Depot，才能繼續其他元件升級
- 支援 VCF Download Tool 進行離線 Binary 下載

### 二、Instance 層級元件（每個 VCF Instance 各自部署）

---

#### 5. Salt Master

| 項目 | 內容 |
|---|---|
| **FQDN** | instcom.dcsn.stone.lab |
| **版本** | 9.1.0.0.25346036 |
| **狀態** | ✅ Running |
| **層級** | Instance（本地） |

**功能說明：**

Salt 架構中的中央編排節點，作為 Salt RaaS 與受管節點（Minion）之間的橋接器。

- 接收來自 Salt RaaS 的指令並分發至目標 Minion（ESXi、vCenter 等）
- 透過 Master Plugin 與 RaaS PostgreSQL 資料庫同步，執行最新組態
- 可連接多個 Salt Master 以支援大規模環境
- 支援以 SSH 或 Aria Automation Cloud Template 部署 Minion

---

| **狀態** | ⚠️ 請至 VCF Operations 確認 |

**功能說明：**

Instance 層級的 SDDC 生命週期管理服務，負責協調本地 Instance 內的元件升級順序。

- 配合 Fleet Lifecycle 執行跨 Instance 的協調操作
- 後續 VCF Instance 升級時（非 Primary），此元件為必要部署項目

#### 8. Real-Time Metrics（即時指標）

| 項目 | 內容 |
|---|---|
| **FQDN** | 需另行指定 |
| **版本** | 9.1.0.0.x |
| **狀態** | ⬜ 未部署（Day-N 選配） |
| **層級** | Instance（本地） |

**功能說明：**

VCF 9.1 全新引入的即時監控能力，以最高 2 秒精度採集基礎架構指標。

- 相容 Prometheus 的 Edge API，支援 ESX、vCenter、vSAN、NSX
- 原生支援 PromQL，可直接作為 Grafana 資料來源
- 提供 3 種採集設定檔：Essentials / Standard / Verbose
- 部署後 Services Runtime 將自動擴充一個 Worker 節點（12 vCPU / 24GB RAM）
- 適用於故障排查（ESXTop 等級的細粒度數據）

## 建議後續動作

1. **確認** SDDC Lifecycle 與 Telemetry 是否已在 VCF Operations → Build / Lifecycle / VCF Management / Components 顯示
2. **確認** License Server 狀態，位於 Fleet Management → License 頁面
3. **評估** 是否部署 Real-Time Metrics（適合需要細粒度監控的生產環境）
4. **評估** 是否部署 Log Management（取代獨立 vRLI，整合至 Services Runtime）
5. **建議** 將 Control Plane 由單節點擴充至 3 節點 HA，以提升生產環境可靠性
